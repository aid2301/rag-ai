# 常见问题

[返回 README](../README.md) · [配置说明](configuration.md) · [Docker 运维](deployment/docker.md)

## 启动与连接

| 现象 | 排查与处理 |
| --- | --- |
| `failed to connect to the docker API` | Docker 引擎未运行或启动失败。先启动 Docker Desktop / Docker Engine，并用 `docker info` 确认服务端可用 |
| 提示缺少 `PG_PASSWORD` 或 `ADMIN_PASSWORD` | 检查项目根目录 `.env` 是否存在，两项是否非空 |
| 数据库连接被拒绝 | 用 `docker compose ps` 检查 db 状态。开发模式默认连宿主 55432，容器中的应用连 db:5432 |
| 修改数据库密码后无法连接 | 已有 PostgreSQL 数据卷不会自动修改密码。恢复与既有数据库一致的配置，或按数据库管理流程修改；不要靠删除数据卷来修复 |
| 端口已被占用 | Compose 调整 `.env` 中的 PORT / PG_PORT；本地开发还要同步调整启动命令与 Vite 代理 |
| 网页能打开但健康状态为 degraded | 检查 `/api/health` 中 `database.connected`，再查看数据库与后端日志；HTTP 200 本身不代表数据库正常 |

查看有限条数的日志：

```bash
docker compose ps
docker compose logs --tail=100 kb
docker compose logs --tail=100 db
```

Docker Desktop 自身崩溃时，先解决引擎问题，不要对包含真实资料的环境直接执行恢复出厂设置或删除持久卷。公开反馈故障时只提供必要且脱敏的日志。

## 登录与模型

**普通用户用 admin 登录失败？**

管理员入口是 `/#/admin`。普通用户界面使用后台创建的账号，管理员令牌不能代替普通用户令牌。

**提示尚未配置模型？**

在后台填写 Base URL、API Key、Model 并测试连接，三项都需要非空。还要确认所选模型支持项目使用的兼容接口与流式输出。

**改了 .env，仍在使用旧模型？**

后台数据库中保存的模型配置优先于环境默认值。先检查后台；修改环境变量后还需要重启进程或重新创建 Compose 服务，见 [配置说明](configuration.md)。

**重启后需要重新登录？**

检查 `SECRET_KEY` 是否改变、`data/secret_key` 是否丢失或不可读写。固定密钥只能保证签名连续性，令牌仍有有效期。

**模型调用超时或出现 401/403/429？**

先用后台测试连接核对地址、凭据、模型权限及服务端限制。复杂问题可先使用较简单模式对照，必要时调整超时和上下文预算。不要把真实 API Key 粘贴到公开 Issue。

## 文档与回答

**PDF 上传失败或提取不到文本？**

当前不内置 OCR。纯扫描件先转换为可提取文字的 PDF、DOCX 或 Markdown，再导入。

**表格有些内容没有进入知识库？**

查看解析正文。XLSX 按工作表转表格，最多输出每表前 500 个非空行，包含表头；公式读取缓存结果。旧 `.xls` 不受支持。

**文件上传报 413？**

检查 `MAX_UPLOAD_SIZE_MB`，默认 50 MB。如果经过反向代理，也要检查代理自身的请求体限制。

**修改文档后回答还是旧内容？**

保存后检查是否处于“待重新解析”，执行重解析并确认同步完成。历史消息不会自动更新，需要重新提问验证。

**文档存在，但回答提示知识不足？**

确认资料里确实有答案、正文成功解析、文档已启用且已同步。问题尽量包含资料中的名称或编号；再检查引用和画像。不要只靠提高模型随机性解决检索问题。

**引用没有页码或看不到原文？**

只有能够提取页码的来源才可能显示页码。小文档全文上下文的来源通常显示“全文”。当前来源卡片展示文档、章节和可用页码，管理员可在文档详情核对正文。

**问题库已经填写标准答案，聊天却没有采用？**

问题反馈记录与可检索的知识文档分开维护。请将知识补充到文档并重解析，标准答案不会自动进入检索库。

**流式输出中途停止？**

检查模型服务和网络连接。经过反向代理时，确认支持长连接且不会缓冲整个 SSE 响应。出现意外断流后重新提问；保留下来的部分内容不是完成状态。

## 测试与 CI

数据库测试连接 `TEST_DATABASE_URL` 指定的独立测试库，默认端口 55433。先运行 `docker compose -f compose.test.yml up -d --wait`；不能用真实数据库替代测试库。

GitHub Actions 当前是模板，仓库中不会自动出现测试运行。启用步骤见 [.github/README.md](../.github/README.md)。上传可执行工作流需要对应的 GitHub 工作流写入权限。
