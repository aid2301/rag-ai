# 使用指南

[返回 README](../README.md) · [配置说明](configuration.md) · [常见问题](troubleshooting.md)

## 角色与入口

| 角色 | 入口 | 主要工作 |
| --- | --- | --- |
| 管理员 | `/#/admin` | 配置模型、管理知识文档和账号、查看审计与用量、处理问题反馈 |
| 普通用户 | `/` | 提问、查看自己的会话与用量、提交问题反馈 |

管理员用户名固定为 `admin`，普通用户账号由管理员创建。两种登录态相互独立；管理员登录不等于已经以普通用户身份进入聊天。

知识库在组织内共享，普通用户的会话与用量各自隔离。管理员可审计会话；目前不提供逐篇文档的用户授权设置。

## 第一次使用

### 管理员准备知识库

1. 登录后台，在模型设置中填写服务地址、API Key 和模型名。
2. 点击“测试连接”，确认服务可以正常返回内容。
3. 在知识库页面上传 `examples/documents/demo-guide.md`。
4. 等待解析完成，打开详情检查正文和章节是否符合预期。
5. 检查文档画像状态，必要时手动生成画像。
6. 在用户管理中创建普通用户，设置用户名、显示名和初始密码。

文档画像概括摘要、主题、实体和可能的问题，辅助检索。画像不是原文的替代品；发现回答不准确时，仍需核对实际解析正文。

### 用户完成问答

使用创建的普通用户登录首页并提出问题。以下是虚构演示资料的核对项，不是对任意模型输出措辞的保证：

| 问题 | 应核对的信息 |
| --- | --- |
| 星桥项目什么时候演示？ | 2030 年 5 月 12 日 |
| 演示地点在哪里？ | 蓝色会议室 |
| 演示样品每次可以借用几天？ | 3 天 |
| DEMO-2048 的样品由谁登记？ | 演示管理员 |
| 星桥项目的预算是多少？ | 资料没有给出预算，应提示信息不足而非编造数值 |

回答后展开“参考来源”，检查文档名称、章节以及存在时的页码。当前来源卡片不是原文全文查看器；管理员可以在文档详情中核对原文。

多轮提问可以继续沿用同一会话。需要分开不同主题时新建会话，避免无关历史影响问题理解。停止生成后可能保留已生成的部分内容；断流或失败应结合页面状态重试，不要将半截回答当作已完成结果。

## 更新与维护文档

### 编辑正文

在详情中修改标题或正文并保存。**保存正文与更新检索结果不是同一个步骤**：文档可能显示“待重新解析”，需要继续执行重解析，或使用页面提供的“保存并重解析”。

重解析成功后，确认同步状态恢复正常，再用一个涉及改动内容的问题验证检索。编辑后的重解析使用当前正文，不会把原始上传文件覆盖掉。

### 启用、停用与删除

- 停用用于临时排除文档的后续检索，适合过期或待核实的资料。
- 重新启用后，再确认解析和同步状态。
- 删除会移除该文档及相关索引；历史回答不会因为原资料变化而自动改写。

资料有不同版本时，在标题和正文中清晰标注版本、生效时间及适用范围，并停用不应继续参与检索的旧版本。系统不能替管理员决定哪个版本具有业务权威性。

### 如何组织资料

优先使用清晰的标题、章节、小节和完整条件说明。把“结论、适用对象、例外、时间范围”放在相关位置，减少答案只命中局部条件的机会。

扫描 PDF 先做 OCR；复杂表格先整理成规则表格。XLSX 只读取公式缓存值，且每个工作表输出最多 500 个非空行（包含表头）；不要把超出部分当作已入库。

## 处理知识缺口与回答错误

用户遇到信息不足或错误回答时，可通过消息上的反馈入口提交给管理员。提交会关联问题、来源消息和上下文快照；同一消息重复提交具有幂等处理，相似问题可能合并计数。

管理员在问题库中：

1. 按状态、分组、来源或热度定位待处理问题。
2. 查看原问题、回答和关联上下文，判断是缺少资料、解析问题还是回答错误。
3. 设置处理人、分组、状态和标准答案；自动分组建议可供参考。
4. 需要让后续问答掌握新信息时，补充或修正文档并重新解析。
5. 用原问题复测，再标记为已解答或归档。

问题状态包括待处理、处理中、已解答、已归档。**填写标准答案不会自动把它写入知识文档或训练模型**；知识库内容仍需通过文档管理维护。

## 查看用量与排查质量

普通用户查看自己的调用与 Token 用量；管理员可查看汇总、用户维度和调用记录。导入画像、问答与部分后台功能均可能产生模型用量，不应只按聊天消息数估算调用量。

发现回答有问题时，依次核对：原资料是否包含答案 → 解析是否正确 → 文档是否启用且已同步 → 来源是否相关 → 所选模式与模型是否适合。具体故障见 [常见问题](troubleshooting.md)。
